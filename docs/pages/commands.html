Command reference

Run commands from inside the repository or any of its worktrees. <agent> is the agent's name in gitta status, usually its branch name.

gitta --help lists every command on one screen. Every command also takes --help or -h. It prints the command's usage and options, exits with 0 and changes nothing. A command given an option it does not know stops before it does anything, names the option and exits with 2. Notes and reasons, as in gitta claim, are free text and may contain anything.

Setup

CommandWhat it does
gitta initWatch this repository and add git hooks for merge, pull and push. Run it once.
--gate "CMD"The test command that decides if combined work is good. gitta runs it on the combined code when you merge, pull or push to the protected branch. Without a gate, gitta still tells agents about clashes, but runs no tests.
--onto BRANCHThe branch to protect. The default is the current branch.
--weakened-checks warn|blockWhat a merge does when it removes tests or weakens a security check. warn reports it and merges, block stops the merge. Local hooks use warn by default, CI and the pull request check use block. Written to .gitta.toml, which takes effect once committed. See Team policy.
--teamWrite the team policy to .gitta.toml, so you can commit it and share the test command and rules with your team and the CI check. See Team policy.
--notify on|offDesktop notifications when something needs a person. Off by default.
--no-claudeDo not add Claude Code hooks.
--no-mcpDo not register the gitta MCP server for Cursor and Codex.
--no-cowOn Linux, use ordinary worktrees instead of a shared checkout.
--security PATTERNTreat this symbol or path as a security check in this checkout. Repeat for more. For the whole team, use a committed .gitta-security file. See Mark your own security checks.
--security-block high|medium|noneThe security notes that count as weakened checks. The default is high. Saved as "security_block" in .gitta/config.json. See Security notes.
--parallel NRun at most N combination checks at the same time.
--server URL[,URL], --token TReport to Gitta Enterprise team servers.
gitta adopt [PATH...] [--all]Coordinate worktrees that another tool made, without automatic watching. --onto BRANCH and --gate CMD work as for init. Not needed after gitta init, which finds worktrees by itself.
gitta adopt --reset <agent>Restart an agent whose start commit is no longer in the repository. Its changes are then counted from where its work meets the protected branch. See Troubleshooting.

Everyday

CommandWhat it does
gitta status [--json]Agents, their changed files and all warnings. A worktree Gitta cannot read is skipped with one line that says why and how to fix it; the others are shown as usual. --json lists them under skipped.
gitta watch [--once]A live terminal view. See Watching gitta work.
gitta sync <agent> [--from main|<agent>]Merge work from main, or another agent's current work, into this agent's copy.
gitta check <agent> [--with <agent>] [--json]Run the gate on this agent's work combined with each other agent's work, or with one. Results are PASSES, BREAKS or DOES_NOT_MERGE.
gitta claim <agent> <symbol or path> [note]Announce a change before it is made.
gitta release <agent> <symbol or path>End a claim.

Watching gitta work

gitta watch fills the terminal and updates as events arrive.

  • Each agent, with what it is doing now.
  • The latest events, one plain line each.
  • Today's counts of changes checked, clashes caught and merges.
  • Anything a person must act on, with the exact command to run. When nothing waits, it says "Nothing needs you".

Press q to quit. The view follows the terminal size and has no colour when NO_COLOR is set. Without a terminal, for example in a pipe, it prints plain lines. gitta watch --once prints today's counts and the recent events, then exits.

The same events go to .gitta/gitta.log, one line each with the time and a plain sentence. Follow it with tail -f .gitta/gitta.log.

Merging

You merge with git merge, git pull or git push. The hooks that gitta init adds run the checks. See Merging. The commands below are optional.

CommandWhat it does
gitta land <agent>Optional. Check, merge, run the gate, and move main forward by one commit, in one command.
gitta land --allOptional. Land every agent, in dependency order.
gitta land <agent> --pr [--remote origin]Push the checked result to gitta/pr/<agent> and open a pull request.
gitta approve <agent> <reason>Optional. A recorded override for a repository that sets weakened_checks to block. A person accepts this agent's current weakened checks, security findings and code page findings, and the reason goes into the audit trail. It runs only at a person's terminal, outside agent sessions and workspaces, and covers only these exact findings.
gitta pr-check --pr REF --other REF[=NAME]...Compare one branch with others, as the CI check does. --name N names this pull request, --base REF sets the target branch, --gate CMD runs your tests on each pair, --json prints the results for scripts. It also lists removed tests and weakened checks in the branch, and exits with 3 when weakened_checks is block. See Pull requests and CI.
gitta encodingWith gitta Enterprise, show the code pages of the mainframe files, from .gitattributes and .gitta-encoding, and the code page risks gitta sees. This command is in the Enterprise build, not in the free gitta. See Set the code page for each folder.
gitta scan [DIR...]Search dependency folders (node_modules, .venv, venv, vendor, or the folders you name) for agent instruction files that a package planted, and for prompt injection phrases in them.

Team policy in .gitta.toml

gitta init --team writes a .gitta.toml at the root of the repository. --weakened-checks writes it too. Commit it. gitta reads it from the protected branch, so only a reviewed commit changes the policy, and the CI check reads the same file. A copy you edit but do not commit changes nothing.

$ gitta init --team --weakened-checks block $ cat .gitta.toml # gitta team policy. Commit this file: merges, pushes and the CI check read it from main. # The test command gitta runs on the combined code before a merge. gate = "PYTHONPATH=src python3 -m unittest -q" # Removed tests or weakened security checks: "warn" lets the merge go ahead and records it, "block" stops it. # Without this line, local merges warn and the CI check blocks. # weakened_checks = "warn" weakened_checks = "block"
KeyUse
gateThe test command for the combined code. A local --gate setting comes first on that machine. CI runners use this one when they get no GATE.
weakened_checkswarn or block. Without it, local merges warn and the CI check blocks. The GITTA_WEAKENED_CHECKS environment variable comes first.

What gitta keeps in .gitta/

Everything stays in the repository's own .gitta/ folder. Git ignores it, and nothing in it leaves the machine.

PathContents
config.jsonThe settings below.
audit.jsonl, audit-mainThe hash-chained audit trail, and the last main commit it recorded. See Audit trail.
gitta.logOne readable line per event, with the time and a plain sentence. Follow it with tail -f .gitta/gitta.log. It is rotated at 1 MB.
activity.jsonlThe same account of what gitta did and why, as JSON.
agents/The workspaces of agents started in a batch. See Agents in batches.
events/, logs/Recent events for gitta watch, and the output of each agent that gitta run started.
approvals.json, claims.jsonOverrides people recorded with gitta approve, and changes agents announced with gitta claim.
base/, cache/parse/The base each agent started from, and parsed files, so warnings stay fast.
shared/, cow/Shared and copy-on-write workspaces on Linux. See Linux workspaces.

To remove gitta, use gitta uninstall. It keeps the work in every agent workspace.

Settings in .gitta/config.json

KeyUse
"gate"The gate command, set with --gate

"parallel"How many combination checks run at once, set with --parallel
"security"Patterns from --security

Environment variables

VariableUse
GITTA_SERVER, GITTA_SERVER_TOKENTeam servers and token, for CI runners and cloud agents. Overrides the repository setting.
GITTA_SERVER_CAA PEM file with your own certificate authority, for team servers with private certificates.
GITTA_ADMIN_TOKENAn admin token for gitta team commands.
GITTA_NO_UPDATE_CHECK1 turns the daily update notice off. The daily check sends only the gitta version, the operating system and the processor type to gitta.io. The notice is also off when CI is set. To turn it off for good, put {"update_check": false} in ~/.config/gitta/config.json.
GITTA_MACHINEThe machine name shown to others. The default is the host name.
GITTA_AGENTSet it in the environment of an agent tool that gitta doesn't recognise. gitta then treats that process as an agent, so it can't run gitta approve. Claude Code, Cursor and Codex are recognised on their own.
GITTA_WEAKENED_CHECKSwarn or block. Comes before .gitta.toml, for one run or one CI job.
GITTA_SKIP1 skips gitta's check for one cherry-pick, rebase, reset or update-ref of the protected branch. The skip is recorded in the audit trail.
GITTA_NO_NOTIFYSet it to keep desktop notifications off for one process.
GITTA_SANDBOX, GITTA_FSPaths to the gitta-sandbox and gitta-fs programs on Linux, when they aren't on the PATH. See Linux workspaces.
GITTA_PROFILE1 prints the time of each step to standard error, for measuring performance.
