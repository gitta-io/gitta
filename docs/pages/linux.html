Linux workspaces

On Linux, gitta can let many Claude Code worktrees share one checkout on disk. It can also run agents in a sandbox. Both are optional.

Shared checkout

A normal worktree is a full copy of the repository's files. Five agents on a large repository need five copies. With a shared checkout, every agent sees a full repository, but only the files it changes are stored separately.

gitta init sets this up for new Claude Code worktrees in the repository. gitta uses the best method that is available:

MethodUsed when
Kernel overlaygitta runs as root.
fuse-overlayfsIt is installed and gitta runs as a normal user.
gitta's own FUSE layerFUSE is available.
Ordinary worktreeNone of the above is available.

Each agent still gets a real git worktree, with its own branch, HEAD and index. The agents share only the files, never their git state, so one agent's staged or committed work never shows up in another agent's worktree.

To make several workspaces at once, run gitta up -n 3 --backend overlay as root, or --backend fuse as a normal user. Each agent gets its own branch, gitta/a1, gitta/a2 and so on. In a repository where you already ran gitta init, the new agents join that setup and branch off your main branch, so you merge their work with git merge as usual. gitta down removes them again.

When the last worktree on a base commit goes away, gitta also removes the shared checkout of that commit, so old checkouts do not pile up.

Cost on compile-heavy workReading through a layer is slower than reading a normal folder, and a compile-heavy test job shows it most. Use the shared checkout when disk space matters more than build time. Turn it off with gitta init --no-cow.

Sandbox

The sandbox builds a fresh, minimal world for the agent with unprivileged Linux namespaces (bubblewrap) and runs the agent in it. Only the agent's worktree, the paths you allow and the toolchain are present. Your home folder, SSH keys, cloud credentials in the environment, the host's sockets, the main checkout and other agents' worktrees are not part of that world, so the agent and every process it starts cannot reach them. The agent keeps full read and write access to its worktree and reaches the network for its API.

Start agents in the sandbox with gitta run --sandbox, or run any command in it directly:

$ gitta-sandbox --workspace ../translate-api -- claude $ gitta-sandbox --workspace ../translate-api --write ~/.cache/pip -- claude
OptionEffect
--read PATHAlso make this path readable in the sandbox.
--write PATHAlso make this path writable, for example a cache folder.
--env NAMEForward one environment variable into the sandbox; the rest of the environment is cleared. gitta forwards the agent's API key for you.
--no-netRun with no network at all (an empty network namespace).

The sandbox needs bubblewrap and unprivileged user namespaces, which modern Linux distributions enable by default. Install the bubblewrap package if it is not already present.

Keep secrets out of reach of agents in any case.
