gitta documentation

gitta coordinates AI coding agents that work in the same repository at the same time. It tells an agent when another agent changes code that its new work uses. It runs inside your normal git merge, tests the combined code before main moves and stops the merge when your tests fail. Removed tests and weakened security checks are reported in the merge output and the audit trail.

gitta runs on top of Git. It uses the normal git command, and your repository format, branches and pull requests stay as they are. It has no AI inside. It reads code with parsers, applies fixed rules and runs your own tests.

Mainframe with gitta Enterprise

gitta Enterprise reads COBOL programs, copybooks and JCL. When one agent changes a copybook field, a paragraph or a program’s interface, every agent whose new code uses it is warned, and the pipeline check can stop a change before your DBB build. JCL, REXX, CLIST, COBOL and assembler changes that give code more authority are reported at merge time and in the audit trail. gitta runs next to the mainframe, on developer machines and CI runners. Nothing is installed on z/OS.

Free and Enterprise

The gitta command is free and open source. It covers everything on one machine, including workspaces, warnings, sync, the merge check, the security checks, the pull request check and the local audit trail.

gitta Enterprise adds a team server. Agents on different laptops, CI runners and cloud agents then warn each other too. Enterprise also adds mainframe support for COBOL, copybooks, JCL and code pages, personal tokens, SSO, a team-wide audit trail and deployments for Kubernetes, Google Cloud, AWS and Azure. The server runs in your own account.
