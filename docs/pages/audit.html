Audit trail

gitta records who started each agent, what it changed, what was checked, what was stopped and what was merged. Every record links to the one before it, so a change to the record is found.

Why an audit trail for AI coding agents

When agents write code, an auditor asks new questions. Which changes came from an agent? Who started it? Was the change tested with the other work merged at the same time? Were tests removed or checks skipped? Git history shows commits and authors. The gitta trail adds the agent, the checks and the decisions around each change, in one record that you can verify and export.

What is recorded

EventWhenContent
agent_startedA new agent worktree appearsTool, branch, starting commit, path
warningAn agent is told about another agent's change, or about a security note on its own new codeKind, symbol, file, the other agent and its machine. For a security note: the rule, severity, file and line
security_allowedAn allow marker or an [allow] entry covers a security noteThe rule, file, line and reason, and whether the agent's own change added the allow
merge_checkedA git merge, git pull or git push to the protected branch passes the checksThe target branch, the incoming commit, the git command, the files and the test command with its result and time
merge_stoppedgitta stops a merge, pull or push because the tests fail on the combined codeThe target branch, the incoming commit, the git command and the failing tests
checks_skippedA merge ran with --no-verify, or a command moved the protected branch with GITTA_SKIPThe target branch, the merge commit and the command
warnedA merge removes tests or weakens a check, and weakened_checks is warnThe findings, the setting and who ran the merge
blockedThe same, and weakened_checks is block, so the merge stopsThe findings, the setting and who ran the merge
checksBefore gitta land moves mainEach check and its result: weakened checks, security, security rules with each note and the threshold, credentials, changed meaning, merge and tests. Also the test command and its time
land_refusedA landing is stoppedThe check that stopped it, and why
landedgitta land moves mainOld and new commit, exact file versions, the agent's commits with authors and trailers such as Co-Authored-By, approvals
reached_mainWork arrives by another route, for example a merged pull request, a push or git mergeThe commits, authors, committers, trailers, and how many name an AI co-author
approvedA person records an optional override with gitta approveWho, the reason, the exact findings

Each event also records the person (Git name and email, operating system user) and the machine. No source code is recorded. gitta records paths, symbols, commits and results only.

The trail is on from gitta init. It is stored in .gitta/audit.jsonl, one event per line.

Read it

$ gitta audit 2026-10-22T14:43:57Z agent_started ci-level dev@workstation git worktree workspace on branch ci-level from e1091763d4 2026-10-22T14:43:57Z agent_started ci99 dev@workstation git worktree workspace on branch ci99 from e1091763d4 2026-10-22T14:43:58Z warning ci99 dev@workstation HAZARD bench.aidev-replay.analyze.wilson in bench/aidev-replay/analyze.py (with ci-level) 2026-10-22T14:43:59Z merge_checked ci-level dev@workstation 2026-10-22T14:44:00Z merge_stopped ci99 dev@workstation 2026-10-22T14:44:00Z reached_main dev@workstation 2026-10-22T14:44:01Z merge_checked ci99 dev@workstation ...

Filter by date, agent or event. --json shows every field of each event:

$ gitta audit --since 2026-10-01 --event merge_stopped $ gitta audit --agent ci99 --json

Check that nobody changed it

Each event carries the SHA-256 hash of the event before it. If someone changes, removes or reorders an event, the chain breaks at that point.

$ gitta audit verify gitta: audit trail intact: 39 event(s), every one linked to the one before $ gitta audit verify # after someone edited .gitta/audit.jsonl gitta: audit trail BROKEN: event 29 (merge_checked, 2026-10-21T09:50:39Z) was changed after it was written

For a record that nobody on a machine can rewrite, use the team server. Each machine sends its events to the servers as they happen, and the servers keep a copy that the machine cannot change. gitta audit verify --team checks that copy.

Export it

$ gitta audit --csv > evidence.csv $ gitta audit --json > events.jsonl time,event,agent,person,email,machine,summary,hash "2026-10-22T09:47:05Z","agent_started","worktree-detect-language","dev","dev@example.com","workstation","Claude Code workspace on branch worktree-detect-language from a975ef6486","ff84c7a4670f0c4281377eb3435ffbdfb33c4a909ae25adb057952961cbfa2e6" "2026-10-22T09:47:05Z","agent_started","worktree-translate-api","dev","dev@example.com","workstation","Claude Code workspace on branch worktree-translate-api from a975ef6486","193096e09832a4f8ead6226bee2d721f4eacaac6613eed156076ddb0cf54de71"

Use CSV for spreadsheets and auditors. Use JSON lines for a log system or SIEM.

Follow new events

gitta audit --follow prints each new event as gitta writes it. Add --json to get one JSON line per event and send it on with any tool. --agent and --event filter the stream, and --since prints the earlier events first.

$ gitta audit --follow --json >> ~/gitta-audit.jsonl $ gitta audit --follow --json | logger --tag gitta $ gitta audit --follow --event landed

Notes on landed commits

Each commit that gitta land makes gets a Git note with the agent, the tool, who landed it and the checks. Notes are a standard Git feature and do not change the commit.

$ git notes --ref=gitta show main | head -14 { "gitta": 1, "agent": "quickfix", "tool": "git worktree", "landed_by": { "name": "dev", "email": "dev@example.com", "os_user": "dev", "machine": "workstation" }, "checks": [ { "check": "weakened checks", "result": "none found" ...

To share notes with your team, push them with git push origin refs/notes/gitta.
